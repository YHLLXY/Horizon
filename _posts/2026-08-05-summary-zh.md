## [Castform Neon 超越 GPT‑5.6 Sol，检索更快更便宜](https://neon.com/blog/how-castform-neon-beats-frontier-models-on-price-and-efficiency) ⭐️ 8.0/10

Castform Neon 通过专门的检索增强技术，在检索准确率上超过 OpenAI 的 GPT‑5.6 Sol，同时成本仅为其一百分之一，Neon 官方博客公布了这一结果。 这表明专用的开源模型能够在成本效益上与旗舰专有系统竞争，降低需要高效知识库查询的组织的门槛。 Neon 采用轻量级检索引擎和 7B 规模的微调模型，评测使用 10,000 条文档检索查询，显示其召回率比 GPT‑5.6 Sol 高约 12%，且每个 token 的成本仅为其 0.01 倍。

## [Meta AI 发布 Muse Spark 1.2，数据贡献者享受更低价格](https://research.meta.ai/blog/introducing-muse-code-and-muse-spark-1-2) ⭐️ 8.0/10

Meta AI 发布了 Muse Spark 1.2，这是其推理型 LLM 的新版本，为允许模型学习其数据的用户提供输入价 10 倍折扣、输出价 20 倍折扣，并在多项基准测试中相较 1.1 版提升了性能。 折扣定价激励用户分享数据，可能加速模型改进，但也引发关于数据隐私和所有权的担忧；同时也让 Meta 在与 Deepseek V4 Flash、Grok 4.5 等 LLM 的竞争中更具吸引力。 定价分为标准计划（$1.25 /M 输入，$4.25 /M 输出）和贡献者计划（$0.10 /M 输入，$0.20 /M 输出），后者需用户同意数据共享，Meta 可将其内容用于产品改进。

## [Webhooks 与 SCROLL：重新思考状态同步](https://weli.dev/blog/the-valley-of-webhooks/) ⭐️ 8.0/10

文章批评了基于 Webhook 的状态同步，并提出了 SCROLL，一种伪 IETF 订阅协议，镜像了现有的 IETF HTTP 订阅草案。 可靠的状态同步对分布式系统至关重要；文章指出 Webhook 的缺陷，并提供一种可标准化订阅机制的协议，可能提升一致性并降低延迟。 SCROLL 通过带 Prefer: stream 头的 GET 请求建立持久连接，类似 HTTP 推送，但作者指出消费者会无论事件频率如何都保持连接，可能导致效率问题。

hackernews · weli · 8月5日 15:22 · [社区讨论](https://news.ycombinator.com/item?id=49184216)

**背景**: Webhook 是将事件推送给客户端的回调机制，但它们可能不可靠、难以去重，并且可能需要轮询以保持一致性。订阅协议，例如 IETF 草案中定义的协议，旨在为客户端通过 HTTP 接收更新提供标准化的拉取或推送机制。博客中描述的 SCROLL 协议镜像了使用 GET 并带 Prefer: stream 的草案，以维持持续的数据流。

## [LLM 0.32 新增推理轨迹、服务器端工具与 OpenAI Responses API 支持](https://simonwillison.net/2026/Aug/4/new-release-of-llm/#atom-everything) ⭐️ 7.0/10

LLM 0.32 引入可视化推理轨迹、服务器端提供商工具、内容可寻址 SQLite 日志，并支持 OpenAI Responses API，默认模型改为 GPT‑5.6 Luna。 这些功能让开发者更清晰地了解模型推理过程，支持更丰富的工具调用工作流，并提升日志效率，便于构建和调试代理式应用。 推理轨迹默认输出到标准错误，可通过 -R/--hide-reasoning 隐藏；服务器端工具包括 OpenAI 的 CodeInterpreter 与 WebSearch，新的 llm openai endpoint 命令可在任何兼容 OpenAI 的端点上一次性执行提示且不记录日志。

rss · Simon Willison · 8月4日 23:58

**背景**: LLM 是一个 Python 库，简化了与大型语言模型的交互，提供统一的 CLI 和 API。它支持多家供应商，并允许插件扩展功能。新版本在之前的基础上增加了调试和日志功能。
