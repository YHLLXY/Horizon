## [Tailscale Traces SQLite WAL Reset Bug to 16‑Year‑Old Issue](https://tailscale.com/blog/sqlite-wal-reset-bug) ⭐️ 8.0/10

Tailscale identified a data‑race in its control‑plane SQLite database caused by the WAL‑reset bug, patched the driver to warn on overlap, and funded an open‑source VFS shim to isolate the race. The incident exposed a long‑standing flaw in SQLite’s WAL subsystem that can corrupt production data, highlighting the need for rigorous race‑condition testing and open‑source collaboration to safeguard critical infrastructure. The bug only manifests when a write transaction collides with a WAL‑reset performed by a checkpoint, a scenario that can arise even in a single‑writer architecture if the writer and checkpoint logic share a connection.

hackernews · ropbear · Aug 12, 14:22 · [Discussion](https://news.ycombinator.com/item?id=49272832)

**Background**: SQLite is a self‑contained, in‑process relational database engine that uses Write‑Ahead Logging \(WAL\) to provide ACID transactions. In WAL mode, a separate checkpoint process may reset the log while a write transaction is active, creating a race condition that can corrupt the database file. Tailscale’s control plane runs a single Go process that accesses a SQLite database to store network state, making it vulnerable to such a race if the driver is not careful.
